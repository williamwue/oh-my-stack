## What Part III shows you

For each Playbook, this part shows you the following.

- When `/poteto-mode` picks the Playbook (for example, it picks "[Bug fix](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/bug-fix.md)" for a request that says "repro first")
- The steps of each Playbook and what each step asks for (for example, "[Hillclimb](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/hillclimb.md)" repeats "one change, one measurement, keep or revert")
- How a Playbook differs from similar ones (for example, use "[Runtime forensics](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/runtime-forensics.md)" to find only the cause, and use "Bug fix" to fix it)

A Playbook is a written procedure that turns the steps a skilled engineer takes naturally into a fixed form.

For example, the bug fix Playbook lays out the order: reproduce, find the cause, fix, and verify in the same place. With fixed steps, any agent that takes the work proceeds in the same order.

Playbooks are reference files inside [`/poteto-mode`](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/SKILL.md), and the user does not call them directly. Even so, knowing what is in them <strong>tells you which words to put in a request</strong>.
