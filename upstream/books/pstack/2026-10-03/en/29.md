This chapter covers [`/figure-it-out`](https://github.com/cursor/plugins/blob/main/pstack/skills/figure-it-out/SKILL.md).

`/figure-it-out` is a Skill for work that no Playbook fits. It designs a procedure that decides the finish condition and the verification mechanism first, and then it proceeds while it keeps a record of decisions.

The `SKILL.md` of `/figure-it-out` has a setting, `disable-model-invocation: true`, that stops the agent from picking and running the Skill on its own based on the conversation. The user calls this Skill, and so does `/poteto-mode`, which sends work that no Playbook fits, and large work, to it ([Chapter 7](https://zenn.dev/sc30gsw/books/7ff701b9811d04/viewer/55bbdb)).

This chapter explains `/figure-it-out` from three angles: when to use it, its procedure, and its output. At the end, it sums up how to choose between this Skill and a similar Playbook.

<a id="how-this-chapter-is-organized"></a>


## How this chapter is organized

This chapter is organized as follows.

- When to use it: large migrations and work you hand off while you step away
- Procedure: five Phases, from Frame to Verify
- Output: it returns the designed Playbook and the path to the decision record
- Example request: /poteto-mode sends work done while you are away to /figure-it-out
- /figure-it-out designs how to carry out one piece of work, and "Orchestrate" runs a whole plan
- Summary

`/figure-it-out` is a <strong>Skill that designs the Playbook itself</strong> for work that matches no Playbook. Before it writes any code, it designs the flow of work, meaning in what order to proceed and what to verify along the way. It also leaves a record so that a person who stepped away can come back and verify the agent's decisions one by one.

<a id="when-to-use-it%3A-large-migrations-and-work-you-hand-off-while-you-step-away"></a>


## When to use it: large migrations and work you hand off while you step away

Use it when the user hands off a migration that spans many callers. Also use it for work that the agent carries on with while the user is away, when the user wants to trust the result after they return.

[Chapter 7](https://zenn.dev/sc30gsw/books/7ff701b9811d04/viewer/55bbdb) covered how `/poteto-mode` sends this kind of work to `/figure-it-out`.

<a id="procedure%3A-five-phases%2C-from-frame-to-verify"></a>


## Procedure: five Phases, from Frame to Verify

`/figure-it-out` splits the work into five stages, which the Skill calls Phases.

It splits the work into stages so that the user can trust the work after they return. It decides the finish condition first, builds the mechanism that verifies, and records decisions as it goes.

In Phase C, the agent repeats the following experiment for each unit.

The agent verifies one unit before it moves to the next. Unlike a check of everything at the end, this order shows right away which unit failed.

When the agent verifies a unit in this loop, it looks at the artifacts themselves, not at what the Workers report about their own work ([Chapter 19](https://zenn.dev/sc30gsw/books/7ff701b9811d04/viewer/d3f914)). Workers are the agents that the main agent handed the work to. For example, it looks at the actual result of running the tests, not at a Worker's report that "the tests passed."

For the same reason, the level of rigor decided in Phase A is not an intention to "look carefully." <strong>The checks the work must pass and the artifacts it must leave set the level of rigor</strong>. To raise the rigor, the agent adds checks that block the next unit until they pass, and it leaves more artifacts, such as verification results and decision records.

<a id="output%3A-it-returns-the-designed-playbook-and-the-path-to-the-decision-record"></a>


## Output: it returns the designed Playbook and the path to the decision record

The reply includes the following.

- The designed Playbook
- The level of rigor and the reason for it
- The path to the decision record
- What it verified against the Phase A finish condition
- What remains unresolved

<a id="example-request%3A-%2Fpoteto-mode-sends-work-done-while-you-are-away-to-%2Ffigure-it-out"></a>


## Example request: /poteto-mode sends work done while you are away to /figure-it-out

The example in the [README](https://github.com/cursor/plugins/blob/main/pstack/README.md) is a request that reaches `/figure-it-out` through `/poteto-mode`.

```
/poteto-mode i'm stepping away. migrate every caller from the synchronous store
to the new async one, keeping behavior identical. i want to trust it was done
right when i'm back.
```

## /figure-it-out designs how to carry out one piece of work, and "Orchestrate" runs a whole plan

`/figure-it-out` designs how to carry out one piece of work, and "[Orchestrate](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/orchestrate.md)" runs a whole plan that spans several days. [Chapter 16](https://zenn.dev/sc30gsw/books/7ff701b9811d04/viewer/3b2bef) has a comparison that also includes "[Autonomous run](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/autonomous-run.md)," which decides the finish condition first and carries one task through without stopping.

## Summary

- <strong>`/figure-it-out`.</strong> For large work that no Playbook fits, it designs a procedure that first builds a finish condition you can verify and a verification mechanism, then verifies unit by unit and keeps a decision record.
- <strong>Choosing between them.</strong> `/figure-it-out` designs how to carry out one piece of work, and "Orchestrate" runs a whole plan that spans several days.
