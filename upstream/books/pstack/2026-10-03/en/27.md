## What Part V tells you

Part V answers the following questions about each Skill.

- What each Skill does and when to use it. For example, `/how` explains what the current code does before you change it.
- What shape of output it returns. For example, `/why` labels each reason it finds with a level that says whether a record backs it or it is a guess.
- Example requests that call it directly, and how to choose between similar Skills. For example, use `/interrogate` to look for weak points inside the diff, and `/blast-radius` to look for what breaks outside the diff.

A Skill packages the steps of a task under a name, so that each call by that name runs the same steps. The tasks include, for example, investigating with `/why`, designing with `/architect`, verifying with `/blast-radius`, and cleaning up with `/unslop`.

`/poteto-mode` calls most of them automatically, as steps of a Playbook.

The user can also call a Skill directly by name. The user calls one directly when they want to change the Skill choice the Playbook made, or when they want a more careful check than the default.

For example, say the diff is small enough that the `/poteto-mode` steps do not call `/blast-radius`, but you do not fully trust the diff. You can call `/blast-radius` directly and verify what that diff could break.

<strong>To call a Skill directly, the user needs to know what it does</strong>. The chapters of Part V explain what each Skill does.

This book orders the chapters along the flow of the work. The flow is as follows.

- Understand the current code ([Chapter 22](https://zenn.dev/sc30gsw/books/7ff701b9811d04/viewer/031877))
- Run several agents in parallel and compare designs and artifacts ([Chapter 24](https://zenn.dev/sc30gsw/books/7ff701b9811d04/viewer/2df1db))
- Implement, and verify that the implementation works ([Chapter 26](https://zenn.dev/sc30gsw/books/7ff701b9811d04/viewer/9884cb))
- Verify what the change could break ([Chapter 27](https://zenn.dev/sc30gsw/books/7ff701b9811d04/viewer/e23752))
- Record decisions ([Chapter 28](https://zenn.dev/sc30gsw/books/7ff701b9811d04/viewer/6638a6))
- Clean up the code (Chapters 29 to 31)
- Clean up the prose ([Chapter 32](https://zenn.dev/sc30gsw/books/7ff701b9811d04/viewer/c22a83))
- Keep what you learned ([Chapter 33](https://zenn.dev/sc30gsw/books/7ff701b9811d04/viewer/7c5f9e))

[Chapter 23](https://zenn.dev/sc30gsw/books/7ff701b9811d04/viewer/ba4cc8) covers the Skill that designs the way of working itself, for work that no Playbook fits. That Skill deals with how the whole task proceeds, not with one step in the flow. So this book treats it apart from the flow.

[Chapter 25](https://zenn.dev/sc30gsw/books/7ff701b9811d04/viewer/e5f103) collects two Skills that extend pstack to fit the user's habits and to work with Grok Bot. Neither Skill belongs to a particular step in the flow, so this book treats them apart from the flow.

[Chapter 34](https://zenn.dev/sc30gsw/books/7ff701b9811d04/viewer/c37697) covers `/setup-pstack`, which sets the models. [Chapter 35](https://zenn.dev/sc30gsw/books/7ff701b9811d04/viewer/9cd5c1) covers `/poteto-mode`, which receives the request first.

The pstack [README](https://github.com/cursor/plugins/blob/main/pstack/README.md) sums up how to get started as "pick models with `/setup-pstack`, and use `/poteto-mode` for work that requires rigor. That's it." The README also says that `/poteto-mode` uses the other Skills as needed.

`/setup-pstack` is the first Skill you use when you start with pstack, and `/poteto-mode` is the first Skill you use each time you start a task. Neither Skill belongs to a particular step in the flow, so this book covers them in chapters apart from the flow.
