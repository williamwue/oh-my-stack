この章では、次の2つのSkillを扱います。

1. [`/automate-me`](https://github.com/cursor/plugins/blob/main/pstack/skills/automate-me/SKILL.md)
2. [`/make-bot-ui`](https://github.com/cursor/plugins/blob/main/pstack/skills/make-bot-ui/SKILL.md)

2つは、どちらも、pstackを利用者の環境に合わせて広げるSkillです。それぞれの用途は次のとおりです。

- <strong>`/automate-me`</strong>・・・ エージェントが、利用者のチャットの履歴から利用者の流儀（例：「段落は短く。選択肢を比べるときは表にする。」）を読み取り、その流儀を書いた、`/poteto-mode` のような利用者専用の mode のSkillを作ります。
- <strong>`/make-bot-ui`</strong>・・・ エージェントが、利用者がボタンを押すと、pstackを入れられるAI Botアプリ Grok Bot（[第5章](https://zenn.dev/sc30gsw/books/080faba713547b/viewer/b6ac2d)）の処理が起動するWebページを作ります。

この章では、2つのSkillを誰が呼ぶのかを確かめたうえで、1つずつ、役割、使いどき、手順の3つの観点で解説します。原文に依頼例があるSkillには依頼例も示します。

## `/automate-me` は、チャットの履歴から利用者の仕事の進め方を読み取り、利用者専用のSkillにする

<a id="%E5%BD%B9%E5%89%B2%EF%BC%9A%E5%88%A9%E7%94%A8%E8%80%85%E3%81%AE%E6%B5%81%E5%84%80%E3%82%92%E3%80%81%E5%B1%A5%E6%AD%B4%E3%81%A8%E8%B3%AA%E5%95%8F%E3%81%8B%E3%82%89%E5%88%A9%E7%94%A8%E8%80%85%E5%B0%82%E7%94%A8%E3%81%AEskill%E3%81%AB%E3%81%99%E3%82%8B"></a>


### 役割：利用者の流儀を、履歴と質問から利用者専用のSkillにする

`/automate-me` は、<strong>利用者の仕事の流儀を、エージェントが従うSkillに変えるSkill</strong>です。出力は、その利用者に合わせた `-mode` という接尾辞を付けた1つのSkillです（例：`jay-mode`）。

利用者は、自分の流儀を説明する必要はありません。<strong>エージェントが、利用者が実際に何度も求めてきたことを、チャットの履歴から読み取ります</strong>。

たとえば、利用者が「返答はもっと短くしてください」と何度もエージェントに言い直していれば、エージェントは「返答は短く」を利用者の流儀として読み取ります。履歴に出てこない意図は、エージェントが利用者に質問して補います。

<a id="%E4%BD%BF%E3%81%84%E3%81%A9%E3%81%8D%EF%BC%9A%E5%88%A9%E7%94%A8%E8%80%85%E3%81%8C%E3%80%81%E8%87%AA%E5%88%86%E3%81%AE%E5%A5%BD%E3%81%BF%E3%82%84%E5%83%8D%E3%81%8D%E6%96%B9%E3%82%92-skill-%E3%81%AB%E3%81%97%E3%81%9F%E3%81%84%E3%81%A8%E3%81%8D"></a>


### 使いどき：利用者が、自分の好みや働き方を Skill にしたいとき

pstackの`/poteto-mode`や他のSkillでも、すべてのユースケースに対応することはできません。  
そこで、利用者は、自分の好みや働き方に合うSkillを作りたいときに、このSkillを名前で呼びます。

「コミットメッセージの書き方」のような1つの作業の手順だけを残したいときは、利用者は、このSkillではなく、Skillのファイルを書くための Cursor 組み込みのSkill `create-skill` だけを使います。1つの作業の手順は、働き方全体をまとめる仕事の流儀のためのSkillではなく、普通のSkillとして書けば足りるからです。

<a id="%E6%89%8B%E9%A0%86%EF%BC%9A%E5%B1%A5%E6%AD%B4%E3%82%92%E8%AA%AD%E3%81%BF%E3%80%81%E5%88%A9%E7%94%A8%E8%80%85%E3%81%AB%E8%81%9E%E3%81%8D%E3%80%81%E4%B8%8B%E6%9B%B8%E3%81%8D%E3%82%92%E7%A3%A8%E3%81%84%E3%81%A6%E3%81%8B%E3%82%89pr%E3%82%92%E9%96%8B%E3%81%8F"></a>


### 手順：履歴を読み、利用者に聞き、下書きを磨いてからPRを開く

1. <strong>履歴を読む</strong>・・・ エージェントは、今のワークスペースの直近2〜4週間のトランスクリプト（チャットの記録）を、たとえば3つの期間に区切り、並列のサブエージェントに読ませます。読むのは今のワークスペースの記録だけで、ほかのプロジェクトの個人的なチャットまで読まないようになっています。2つ以上の期間で見つかったパターンだけを確度が高いとみなし、1つの期間にしか出てこないパターンは、通常は捨てます。1度だけ言われて、別の場面では逆のことを言われた、というような好みは、流儀ではなく雑音だからです。
2. <strong>利用者に直接聞く</strong>・・・ エージェントは、履歴にまだ出てきていない意図を補うため、選択式の質問を1〜2問と、自由記述の質問を1問だけ聞きます。選択式にするのは、利用者が一から文章を書かずに済むようにするためです。
3. <strong>下書きする</strong>・・・ エージェントは、`create-skill` で `.cursor/skills/<handle>-mode/SKILL.md` に下書きを書きます。`<handle>` には、利用者の名前や、利用者が選んだ識別子が入ります。
4. <strong>磨く</strong>・・・ エージェントは、下書きに、AIらしい文章の癖を取り除く `/unslop`（[第32章](https://zenn.dev/sc30gsw/books/080faba713547b/viewer/44857b)）をかけ、本人らしく読めるかを利用者と確かめます。
5. <strong>取り込む</strong>・・・ エージェントは、worktree（1つのリポジトリから、作業用のコピーを複数作るgitの機能。[第18章](https://zenn.dev/sc30gsw/books/080faba713547b/viewer/cdc49b)）で作業してPRを開きます。main に直接 push はしません。

既存の mode のSkillがあれば、エージェントは、前回の編集以降の履歴だけを読んで、そのSkillを更新します。

エージェントは、<strong>利用者にエージェントの既定の振る舞いと異なる具体的な規則があるときだけ、Skillに節を作り</strong>、「明確に伝える」のような一般論は書きません。一般論はエージェントの振る舞いを変えないので、書いても読む手間が増えるだけだからです。

たとえば、「段落は短く。選択肢を比べるときは表にする。箇条書きは項目が本当に並列なときだけ。」のような規則なら、節を作ります。

<a id="%E4%BE%9D%E9%A0%BC%E3%81%AE%E6%9B%B8%E3%81%8D%E6%96%B9%EF%BC%9A%E3%82%B3%E3%83%9E%E3%83%B3%E3%83%89%E3%81%A0%E3%81%91%E3%81%A7%E5%A7%8B%E3%82%81%E3%82%89%E3%82%8C%E3%82%8B"></a>


### 依頼の書き方：コマンドだけで始められる

同梱ガイドの [`09-make-it-yours.md`](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/09-make-it-yours.md) によると、利用者は、次のようにコマンドだけを打てば始められます。利用者の流儀は、エージェントが履歴から読み取るので、利用者が説明を書き添える必要はありません。

```
/automate-me
```

同じページは、働き方が変わったときに、既存の mode のSkillを更新する依頼も載せています。

```
/automate-me update my mode skill with everything since its last edit
// 前回の編集以降のすべてを使って、私の mode のSkillを更新して
```

## `/make-bot-ui` は、送信キーを外に出さずに、Grok Bot をボタンで起動するページを作る

<a id="%E5%BD%B9%E5%89%B2%EF%BC%9A%E7%A7%98%E5%AF%86%E3%81%AE%E5%80%A4%E3%82%92%E3%82%A8%E3%83%BC%E3%82%B8%E3%82%A7%E3%83%B3%E3%83%88%E3%81%AB%E8%A6%8B%E3%81%9B%E3%81%9A%E3%81%AB%E3%80%81bot%E3%82%92%E8%B5%B7%E5%8B%95%E3%81%99%E3%82%8B%E4%BB%95%E7%B5%84%E3%81%BF%E3%82%92%E7%B5%84%E3%81%BF%E7%AB%8B%E3%81%A6%E3%82%8B"></a>


### 役割：秘密の値をエージェントに見せずに、Botを起動する仕組みを組み立てる

`/make-bot-ui` は、利用者がクリックするページを作り、そのボタンで <strong>Grok Bot を webhook 経由で起動する仕組み</strong>を組み立てるSkillです。

<a id="%E4%BD%BF%E3%81%84%E3%81%A9%E3%81%8D%EF%BC%9Agrok-bot-%E3%81%AE%E3%83%AB%E3%83%BC%E3%83%86%E3%82%A3%E3%83%B3%E3%82%92%E3%80%81webhook-%E3%81%A7%E3%83%9C%E3%82%BF%E3%83%B3%E3%81%8B%E3%82%89%E8%B5%B7%E5%8B%95%E3%81%97%E3%81%9F%E3%81%84%E3%81%A8%E3%81%8D"></a>


### 使いどき：Grok Bot のルーティンを、webhook でボタンから起動したいとき

利用者は、Grok Bot を webhook で起動するページ（ボタンやダッシュボード）を作りたいときに、このSkillを使います。そのページのために送信キーを提出するときや、ページを Tailscale で公開するときも、このSkillを使います。

<aside class="msg message"><span class="msg-symbol">!</span><div class="msg-content">
<p class="code-line" data-line="87"><a href="https://tailscale.com/" rel="nofollow noopener noreferrer" target="_blank"><strong>Tailscale</strong></a>・・・ 利用者が持つ端末（パソコンやスマートフォンなど）同士を、インターネットに公開せずにつなぐ非公開のネットワークを作るサービス。このネットワークを tailnet と呼び、tailnet に入っている端末からだけ、そのネットワーク上のページを開ける</p>
</div></aside>

Grok Bot はAI Botアプリで、pstack をプラグインとして入れられます（[第5章](https://zenn.dev/sc30gsw/books/080faba713547b/viewer/b6ac2d)）。Grok Bot には、ルーティンを登録できるため、スケジュールやイベントをトリガーに動作させることができます。

<aside class="msg message"><span class="msg-symbol">!</span><div class="msg-content">
<p class="code-line" data-line="93"><strong>webhook</strong>・・・ 指定したURLにHTTPリクエストを送ることで、別のシステムにイベントを知らせ、処理を起動する仕組み（例：GitHubへのpushをきっかけに、指定したURLへ通知を送る）</p>
</div></aside>

`/make-bot-ui` が扱うのは、webhook をきっかけに起動するルーティンです。ボタンを押してから Grok Bot の処理が始まるまでに、次の3つが順に動きます。

1. 利用者がブラウザでページのボタンを押すと、ページは、Botと同じコンピューターで動く小さなサーバー（以下、ローカルのサーバー）に、ボタンに対応するJSON（例：`{"action": "summarize-today"}`）を送ります。
2. ローカルのサーバーは、受け取ったJSONに送信キーを付けて、ルーティンの webhook URL（そのルーティンを外から起動するための専用のURL）に送ります。
3. webhook URL にJSONが届くと、Botのルーティンが起動し、そのJSONを入力として処理を始めます。

ページが webhook URL に直接送らず、<strong>間にローカルのサーバーを挟むのは、送信キーをブラウザに渡さないため</strong>です。理由は、この後の手順の説明で見ます。

### 手順：ルーティンを作り、ページを置いて、tailnet で公開する

1. <strong>ルーティンを作る</strong>・・・ エージェントは、webhook で起動するルーティンを作り、POSTの本文を信頼できないデータとして扱うようプロンプトに書きます。webhook URL に届く本文は外から送られてくるので、本文に「これまでの指示を無視して」のような指示の文が紛れ込んでいても、Botがその文に従わないようにするためです。
2. <strong>URLを取ってもらう</strong>・・・ エージェントは、利用者に、Routines（Botのルーティンの一覧）からルーティンを開き、webhook URL をコピーしてもらいます。原文は、webhook URL はチャットに貼ってもらってよいとしています。一方、次の手順の送信キーは、チャットに貼ってもらいません。
3. <strong>送信キーを受け取る</strong>・・・ 送信キーは、webhook を呼ぶ正当な送り手であることを示す秘密の値です。エージェントは、送信キーをチャットでは受け取らず、秘密の値を入力する専用のカードで利用者に提出してもらいます。提出されたキーの値はエージェントには見えず、エージェントは値を見ないまま、その値をサーバーの設定に書き込みます。
4. <strong>ページを置く</strong>・・・ エージェントは、ページとローカルのサーバーを、Botと同じコンピューターに置きます。ページのボタンはローカルのサーバーにPOSTし、そのサーバーが送信キーを付けて webhook にPOSTします。
5. <strong>tailnet に載せる</strong>・・・ エージェントは、Tailscale で、インターネットに公開せずに、利用者の端末からページを開けるようにします。
6. <strong>起動を受け取る</strong>・・・ Botは受け取ったJSONを、指示ではなく外部のデータとして扱います。

<strong>エージェントは、送信キーをサーバーにだけ置き、ブラウザやチャットには出しません</strong>。キーを知っていれば、誰でもそのルーティンを起動できてしまうからです。

ブラウザから直接 webhook を呼ぶと、ページのコードにキーを書くことになり、ページを開いた人なら誰でもキーを読めてしまいます。そのため、ボタンは必ずローカルのサーバーを通して webhook を呼びます。

また、秘密の値をチャットに出さないという同じ方針で、エージェントは Tailscale の認証情報も利用者に聞きません。代わりにログインURLを渡し、利用者自身にブラウザで端末を承認してもらいます。

## まとめ

- <strong>2つのSkillの呼び方</strong>・・・ `/automate-me` と `/make-bot-ui` は、利用者が名前で呼んだときだけ動きます。
- <strong>`/automate-me`</strong>・・・ チャットの履歴と利用者への質問から、利用者の流儀を書いた利用者専用の `-mode` Skillを作ります。
- <strong>`/make-bot-ui`</strong>・・・ 送信キーをチャットにもブラウザにも出さずに、ボタンで Grok Bot を起動するページを作ります。

次の[第26章](https://zenn.dev/sc30gsw/books/080faba713547b/viewer/03ebca)では、検証の仕組みを作り、アプリに合わせ続ける2つのSkillを扱います。見ていくのは、[`/create-verification-skill`](https://github.com/cursor/plugins/blob/main/pstack/skills/create-verification-skill/SKILL.md)、[`/maintain-verification-skill`](https://github.com/cursor/plugins/blob/main/pstack/skills/maintain-verification-skill/SKILL.md)です。
