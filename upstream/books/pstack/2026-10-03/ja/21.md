## 第4部で分かること

- 各Principleが何を選び、何を避けるか、それが必要な理由（例：『[<strong>Prove It Works</strong>](https://github.com/cursor/plugins/blob/main/pstack/skills/principle-prove-it-works/SKILL.md)』は、ビルドが通っただけでは完了とせず、書き出したファイルや画面を直接確かめる）
- 各Principleが当てはまる場面と、当てはまらない場面（例：『[<strong>Outcome-Oriented Execution</strong>](https://github.com/cursor/plugins/blob/main/pstack/skills/principle-outcome-oriented-execution/SKILL.md)』は、計画済みの移行では使うが、区切りのない普段の小さな修正には使わない）
- 依頼の中で、Principleの名前を使ってエージェントの作業の方向を変える方法（例：`apply prove it works.` と書き、実際にインポートを流して、書き込まれたレコードを見せるよう求める）

Principleは、<strong>エージェントが作業の途中で下す判断の基準</strong>です。Playbookは作業の順番を決めますが、エージェントが各手順を進める中には、「この抽象化を追加すべきか」「コンパイルが通った今、完了と言ってよいか」といった判断が残ります。こうした場面で、エージェントは、Principleに沿って「この変更を入れるか」「まだ完了と言えないか」を決めます。

23件のPrincipleは、扱う判断の種類ごとに、次の5つのグループに分かれています。グループが分かれているので、読み手は、いま迷っている判断の種類から、読むべき章を選べます。

Principleは、利用者が明示的に呼び出すものではなく、<strong>エージェントが、作業が当てはまる場面かどうかを判定して読むもの</strong>です。

`/poteto-mode`（作業を始めるときに使うSkill。[第7章](https://zenn.dev/sc30gsw/books/080faba713547b/viewer/4fda7d)）は、手順が複数ある作業の始めに、Principleの索引を読みます。

索引は `/poteto-mode` の `SKILL.md` にある一覧で、各Principleの名前と、当てはまる場面（例：『Prove It Works』なら「作業を終えた後、完了を宣言する前」）が1行ずつ書かれています。エージェントは、作業がその場面に当てはまったPrincipleについて、本体の `SKILL.md` を全文読んでから適用し、返答の中で、適用したPrincipleの名前と、それによって変わった判断を挙げます。

<strong>エージェントが作業の始めに読むのは、Principleの名前と当てはまる場面の一覧だけです</strong>。本文は、作業がその場面に当てはまったときにだけ読み、判断に使います。そのため、23件すべての本文を毎回読み込まずに済み、コンテキストを無駄に使いません。

利用者は、この仕組みを、<strong>依頼にPrincipleの名前を書くこと</strong>で明示することもできます。エージェントが当てはまる場面を見落としているときに、依頼にPrincipleの名前を一言書けば、エージェントはその名前が指すルールに沿って作業の方向を修正できます。

Principleの名前を一言書くことは、長い指示を書くより正確に伝わります。名前が、そのPrincipleの `SKILL.md` に書かれた完全なルールを指すので、利用者が具体的なPrincipleの中身を伝え直す必要がないからです。

たとえば、ビルドが通っただけで完了を宣言しようとしているエージェントには、同梱ガイド（pstackに同梱されている `docs/guide/` のガイド。[第6章](https://zenn.dev/sc30gsw/books/080faba713547b/viewer/33f073)）の [`docs/guide/08-principles.md`](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/08-principles.md) にある例のように書きます。

```
apply prove it works. run the real import flow and show me the written records.
// prove it works を適用して。実際のインポートを流して、書き込まれたレコードを見せて。
```
