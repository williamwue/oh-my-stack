# Configure pstack models in T3 Code

Use this in place of setup-pstack's model detection, budget, and sheet steps when T3 Code's orchestration tools are available. Keep its optional verification-skill offers. It writes the T3 model sheet, `~/.config/t3-pstack/models.md` (`$XDG_CONFIG_HOME/t3-pstack/models.md` when that is set), one per machine. Every pstack skill reads it on T3 before it dispatches, per [the T3 mapping](../../poteto-mode/references/t3-tools.md). The native `pstack-models.md` sheet, CLAUDE.md, AGENTS.md, and hook trust stay unchanged.

### 1. Detect available models

Call `orchestrator_capabilities`. Its provider instances and their models are the dependable source. A target is valid only when its provider instance can run a child task and lists the model. Its list is short, so search for a model the user names before calling it unavailable. Note each provider's own option IDs and values, such as `effort` on Claude, `reasoningEffort` on Codex and Grok, and `thought_level` on Antigravity. Never write a target you have not seen there. The aliases `inherit-parent` and `auto` are always valid.

### 2. Load current state

The default role-to-target mapping is the sheet in step 5. If the sheet exists, read it and treat its `# budget` line and its role values as the current choices. If it does not, read `t3-pstack-models.md` in the host's config directory (`$CLAUDE_CONFIG_DIR` or `~/.claude` on Claude Code, `$CODEX_HOME` or `~/.codex` on Codex) the same way. Otherwise, if `~/.t3/pstack-models.md` or a project's `.agents/pstack-models.t3.md` exists from OMS 2.x, read its rows as the user's choices: rewrite `<provider>/<model> @<level>` as `<provider>/<model> <optionId>=<level>` with the option ID the provider lists, and drop its `default effort` line. Otherwise start from the defaults.

Drop a line whose role is not in step 5, such as `how explorer` or `architect runners`, which name retired roles, and any value that is not a T3 entry, such as a bare family name or a native model slug. An Antigravity entry's `thinking_level` option becomes `thought_level` at the same value where `orchestrator_capabilities` lists `thought_level` for its model. Every other value is the user's choice and stays, including every `inherit-parent` or `auto` value. Tell the user which lines you dropped or rewrote.

### 3. Budget, map, and confirm

**(a) Ask for a budget.** Ask a structured multiple-choice question (`AskUserQuestion` on Claude Code, numbered options in plain text elsewhere) with these exact labels, naming the current budget when the sheet records one. With no sheet, say that `large` matches the defaults.

- `large - xhigh reasoning`
- `medium - high reasoning`
- `small - medium reasoning`

**(b) Apply it.** Build the working table from the defaults, and on a re-run keep any role you changed by provider, family, list, or alias. Each role's target effort is its default's effort moved by the budget: `large` keeps it, `medium` lowers it one step, and `small` lowers it two steps, on the ladder `xhigh` > `high` > `medium` > `low`. No role runs above `xhigh`, and a target at the bottom stays there. Set the reasoning option of every entry in the role, panel entries included, to the role's target, using the option ID that provider lists. If the provider does not offer that value, use its highest value at or below the target, else mark the role as needing a choice. `inherit-parent` and `auto` do not change. Never write `fastMode`, which on T3 is a priced fast mode.

**(c) Show the roles and confirm.** Show every role with its entry, marking any target not in the detected set as needing a choice, and list each line step 2 dropped. Ask whether to accept as-is or change specific roles, offering the detected targets at `xhigh` or below plus `inherit-parent` and `auto`. A panel role (`arena runners`, `interrogate reviewers`, `thermos reviewers`) takes a list, one child per entry, so the list length sets the count. Each panel list and `arena cross-judge pool` needs at least two model families among its targets. A model's family is the first segment of its ID's last `/` part, such as `claude`, `gpt`, or `gemini`, except that a Fable model is its own family. Arena runs one judge from `arena cross-judge pool`, the first value from a vendor other than the parent's, so order it by preference. Fable and the other Claude models are one vendor, and an `inherit-parent` or `auto` value never judges.

**(d) Ask about the session-start hook.** Ask whether the session-start hook should keep telling new T3 chats when to enter `/poteto-mode`. Write `session hook: on` or `session hook: off`.

### 4. Validate

Write the candidate to a temp file. Call `orchestrator_capabilities` again and save its result to a temp file as `{"providers": [...]}`, copying verbatim the entry of every provider instance the candidate or the defaults name, and adding to each provider's `models` every model they name that the short list omits, as `search` with that model's ID returns it. Run `node <setup-pstack>/scripts/t3-sheet.mjs <candidate> <catalog.json>`, where `<setup-pstack>` is the absolute path of the folder that holds setup-pstack's `SKILL.md`, and fix every line it prints. If `node` is missing, check each entry against the catalog by reading, and say so. A role with no line runs on its default, so add a line for any role whose default this machine cannot run.

### 5. Write the sheet

Overwrite the sheet with the candidate, creating its directory and writing through any symlink at its path. The candidate carries the `# defaults: 3` line and a `# budget` line with the chosen label and the effort it names. If a different file is already there, run the checker on it and ask before you replace it. Overwrite the whole file so re-runs stay idempotent. Then replace `t3-pstack-models.md` in the host's config directory with a link to the sheet (`ln -sf`), so every backend reads the same sheet. With every default kept, the sheet reads:

```markdown
# pstack model configuration (T3). One line per role. Delete a line to fall back to the skill default.
# `inherit-parent` or `auto` as a value: the role runs on the parent chat's model (`delegate_task` omits `target`). Alias entries in a panel list still count toward its fan-out.
# defaults: 3
# budget: large (xhigh)
feature, refactoring: claudeAgent/claude-opus-5-5 effort=xhigh
bug-fix: claudeAgent/claude-opus-5-5 effort=xhigh
perf-issue: claudeAgent/claude-opus-5-5 effort=xhigh
hillclimb: claudeAgent/claude-opus-5-5 effort=xhigh
judgment and prose: claudeAgent/claude-opus-5-5 effort=xhigh
strongest judgment: claudeAgent/claude-fable-5-2 effort=high
arena runners: claudeAgent/claude-fable-5-2 effort=high, claudeAgent/claude-opus-5-5 effort=high, antigravity/gemini-4-neon thought_level=xhigh
arena cross-judge pool: claudeAgent/claude-opus-5-5 effort=high, antigravity/gemini-4-neon thought_level=xhigh
swarm workers: claudeAgent/claude-opus-5-5 effort=high
interrogate reviewers: claudeAgent/claude-fable-5-2 effort=high, claudeAgent/claude-opus-5-5 effort=high, antigravity/gemini-4-neon thought_level=xhigh
thermos reviewers: claudeAgent/claude-fable-5-2 effort=high, claudeAgent/claude-opus-5-5 effort=high, antigravity/gemini-4-neon thought_level=xhigh
no-comments reviewer: claudeAgent/claude-opus-5-5 effort=xhigh
session hook: on
```

### 6. Confirm

Tell the user the sheet was written and that it applies to new sessions. Re-running this skill updates it. Configuration alone starts no workers and does not change the parent chat's model or effort.
