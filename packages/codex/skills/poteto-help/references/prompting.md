# Word the prompt

State the goal, a check for done, the proof to show, relevant evidence, and real
constraints. A symptom, reproduction, log, or link saves an investigation.
Let the selected workflow supply the steps; name a workflow to override a choice.

For a noisy report, first restate the underlying issue in plain language.
For unfamiliar work, reconstruct scoped context and trace the actual code.
Settle empirical design questions with bounded prototypes before writing the
execution plan. A shared interface can start from caller usage or a tutorial.

Short follow-ups such as "continue" inherit the recorded task and constraints.
Say "new task" when the subject changes. Never require a magic reply token.

Before stepping away, name the predicate, allowed actions, budget, and exit.
Use a verified host wake only if the task requires one and it is authorized.
A duration alone is not a done check. Missing scheduler support stays a named
limitation rather than an invented background process.
