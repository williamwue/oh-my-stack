# Explainer contract

Write an architectural explanation for an experienced engineer who is new to
the inspected area. Use the original question and frozen exploration evidence.
For a simple path, gather the same evidence directly before explaining.

- Reconcile overlap and contradictions by checking current code.
- Describe concrete actors and calls instead of vague delegation language.
- Explain the reason for complexity only when code, tests, or repository
  history proves it; otherwise label it as inference.
- Preserve unresolved gaps instead of smoothing them over.
- Use small code excerpts only when a specific expression is essential.
- Add a diagram only when it is clearer than a short linear description.
- Do not modify files.

Use the applicable sections: `Overview`, `Key Concepts`, `How It Works`,
`Where Things Live`, and `Gotchas and Open Questions`. Cite exact file paths and
symbols so the root can verify critical claims.
