# OMS 当前模块双参考审查

本轮覆盖当前仍有效的源码，包括历史实现中仍在使用的模块。官方 pstack
是直接基准，pstack-claude 是第二参考。逐模块结论和字节指纹保存在
`upstream/module-reviews.json`，最终状态以[集成验收记录](../../acceptance/2026-10-23-module-review/result.md)为准。

官方固定为 pstack 0.15.30，提交
`4ec7ffa173eaa70d3d9467a627baf0954645a353`；第二参考固定为
pstack-claude 0.9.102，提交 `356c6e0f978df729eb16f227d795f34d221c5aad`。
第二参考声明的官方基准较旧，不能把所有差异都视为它主动改进的结果。

审查按输入契约、失败处理、资源与进程边界、相关测试和宿主能力比较。
有明确收益的实现与证据规则会适配；本地独有能力和保留官方实现的模块，
也必须写明检索范围与理由。第二参考的自动启用、额外审批和特定模型面板
不会因为出现在参考仓库中就自动成为 OMS 默认策略。

本轮代码与本地验收已完成，最终覆盖 229 个模块、764 个文件；27 项能力适配、
1 项明确不采用。第四轮独立审查无遗留发现，全量检查 944 项通过、40 项跳过。
四个生成包的 64 项 Node/Bun 独立运行检查通过。详细结果及未执行项以集成验收记录为准。

报告保留各审查者提出问题时的原始结论，修复与最终采纳结果由集成验收记录
统一说明。它们没有各自宣布整个项目验收完成。当前源码覆盖不代表审查了
所有已删除 Git 版本，也不证明每次未来决策都最优。

维护命令与后续变更要求见[完整模块审查机制](../module-review.md)。
真实 CC 模型验证仍在本轮范围之外；本地夹具、原生 Pi 模拟提供方、安装
验收和发布是不同的证据。
