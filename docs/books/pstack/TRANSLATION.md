# 翻译、校对与维护

## 内容基线

本书原作者为 kaito。日文是中文翻译的主要依据，作者英文版用于交叉核对。
英文收录保留作者正文，只整理 Markdown、书内链接和阅读导航。
作者许可记录见 [AUTHORIZATION.md](AUTHORIZATION.md)。

每一章对应独立来源文件。来源 URL、页面更新时间、采集时间和正文 SHA-256
记录在来源清单与快照清单中。插件版本描述原书的技术背景，不能代替书籍正文版本。
目录采集成功不等于正文完整；正文提取和来源结构核对通过后才能进入翻译。

## 翻译约定

- 按原文小节逐一翻译，保留例子、表格、脚注、引用和作者限定。
- 作者第一人称仍指 kaito。观点、推测、个人经验与已验证事实保持原有区别。
- 命令、路径、标识符、配置值以及影响示例行为的字符串保留原样。代码块中的说明性注释、提示词和 Markdown/YAML 文档文字译为中文；必须保留原文的行为性字符串，在代码块附近明确说明其含义，并在逐块差异记录中写明理由。
- Skill、Principle、Playbook 使用 [术语表](zh-CN/GLOSSARY.md) 中的统一形式。
- 数字、否定、条件、程度和因果关系需要逐项对照，不能为了流畅而改变技术含义。
- 保留原文历史版本。发现过时信息时加项目注，不将现状改写成作者当时的表述。
- 日英内容有差异时，以日文为中文译本依据，并在该章校对记录中说明差异。
- 项目补充内容标为「Oh My Stack 项目注」，或放入独立配套说明。
- 原文已有的未运行示例、占位变量及伪代码保持原有身份，不能据此声称运行成功。

## 每章状态

| 状态 | 意义 | 所需证据 |
| --- | --- | --- |
| `not_started` | 未翻译或未收录 | 来源目录项 |
| `draft` | 中文初稿 | 完整译文文件及对应来源 |
| `imported` | 英文已收录 | 英文来源及内容一致性记录 |
| `reviewed` | 已完成对照校对 | 逐章校对记录、问题处理结果 |
| `ready` | 本地发布候选 | 校对和结构检查通过，阅读验收无阻塞问题 |

`ready` 表示达到记录中的校验范围，不等于已经公开发布，也不表示作者亲自审定。
AI 校对、人工审阅和作者审定分别记录；没有相应记录时不声称已经完成。
进度同时观察章节数与来源篇幅。分部导读与长技术章的工作量不同。

## 校对要求

逐章检查标题和小节是否完整，例子与列表是否遗漏，代码与原始来源是否一致，
术语和引用是否统一。技术校对重点检查权限、模型选择、委派边界和验证结论。
校对者必须查看对应来源，不能仅凭译文是否流畅作出忠实性结论。

结构工具负责章节、文件、路径、锚点、代码和元数据的一致性。
结构检查通过不能替代语义校对。读者报告的问题保留来源位置、修复说明与校对范围。

## 更新流程

1. 比较来源更新时间与正文哈希，列出新增、删除和改动的章节。
2. 固定新来源快照，保留旧快照的历史归属。
3. 更新受影响的英文内容和中文译文；共享术语变化再检查全书。
4. 对改动章节重新执行结构检查、对照校对和阅读检查。
5. 更新来源清单、章节状态与更新记录。

来源获取可能需要网络；日常内容校验应能离线运行。
长视频与第三方交互内容保留出处链接。图片与图表的文字不能在中文翻译中被悄悄省略。
