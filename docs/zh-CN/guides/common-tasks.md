# 按任务选择入口

[English](../../guides/common-tasks.md) | [简体中文](common-tasks.md)

在 Codex 的 Skill 选择器选择 `oh-my-stack:<入口>`，再发送请求。
在 Claude Code 的请求前加上 `/oh-my-stack:<入口>`。
以下代码块是对话请求，不是终端命令。

## 修 bug

选择 `poteto-mode`，将示例替换为你的复现步骤：

```text
重试后，导出的数据出现重复行。
先复现失败并查明原因，再修复，最后重复同一检查。
改动范围仅限此缺陷。不要发布或合并。
```

预期结果是复现证据、范围明确的代码修改和验证结果。
该请求允许修改代码、测试并运行本地检查。开始前说明数据、服务或网络限制。

## 开发功能

选择 `poteto-mode`：

```text
为订单页添加只显示未发货订单的筛选条件。
保留现有默认视图，并用项目已有检查方式验证两个视图。
未明确的产品决策先提问，再实现。
不要部署或合并。
```

预期结果是指定范围内的实现，以及行为符合要求的证据。
该请求允许修改项目文件并执行相关本地验证。

## 澄清需求

选择 `grill-with-docs`：

```text
帮我设计订单部分取消功能。
对未解决的决策提问并给出建议。
术语和决策经我们确认后再记录。
不要实现代码。
```

预期结果是分轮提问并等待你回答。决策明确后，Skill 可能更新 `GLOSSARY.md` 和架构决策记录。
仅需访谈、不更新这些文档时，选择 `grill-me`。

## 审阅改动

选择 `interrogate`：

```text
审阅当前相对于 main 分支的改动。
检查实际可触发的正确性问题和超出需求范围的修改。
只读审阅。每项具体发现附上文件引用和证据。
```

预期结果是固定的审阅范围、独立发现和最终判断。
审阅可以在只读任务范围内执行相关检查，不直接修复代码。
如果连执行检查也不允许，在请求中明确说明。

## 寻找值得改进的模块

选择 `improve-codebase-architecture`：

```text
检查订单模块的设计改进机会。
生成原版架构报告，展示候选项并等我选择。
不要实施重构。
```

预期结果是只读探索及写入操作系统临时目录的 HTML 报告。
原版 Skill 会尝试在浏览器中打开报告。打开失败时，使用返回的文件路径。
完整样式和图表需要访问上游 CDN。

## 询问该选哪个入口

选择 `poteto-help`：

```text
我准备创建 PR，想先审阅当前分支。
应该用哪个入口，提示词怎么写？
```

预期结果是用法解释和一条建议提示词。决定执行后，单独发送该提示词。

## 单独请求发布

实现、审阅、创建 PR 是不同的请求。
需要发布或合并时，明确仓库、目标分支和外部操作。
模型映射和检查通过均不授予发布权限。
