# T3 Code 适配

## 基线与差异

OMS 2.0.0 基于 michael-denyer/pstack-claude 0.9.138，提交为
`a12b04786023e762f12f5de7bb5fafb8c23f8c36`。
仓库通过保留双亲的合并接入上游历史，后续直接合入 pstack-claude；不独立同步官方 Cursor pstack。

OMS 的运行时差异限于：

- `poteto-mode/references/t3-tools.md`：T3 工具映射。
- `tools/generate.mjs`：为 poteto-mode 和 Codex 工具映射生成条件读取入口。
- 原生 marketplace 名称改为 `oms`，插件名和技能命名空间仍为 `pstack`。
- OMS 自身的版本、文档、适配测试及旧版证据归档。

上游模型表、工作流步骤、hooks、其他宿主适配和原作者声明保留。
T3 通过现有后端安装插件，不作为新的模型供应商或独立运行时加入上游 RUNTIMES。
现有个人角色配置不属于插件默认值，不随源码更新写入。

## 加载方式

代理读取 poteto-mode 时，条件入口要求它在会话提供 T3 Code 工具时读取 T3 映射。
Codex 工具映射也有同样的入口，避免直接进入其他技能后误用 Codex 派发方式。
生成器维护这两行，并使用上游的链接校验检查映射是否存在。
没有 T3 工具时，条件不成立，继续遵循上游行为。

此机制依赖宿主向会话提供插件技能，以及模型遵守读取指令；它不是额外的执行引擎。
上游和宿主的权限规则仍然有效。T3 映射只解决工具选择，不授予派发、外部写入或发布权限。

## 维护与同步

维护者为 pstack-claude 设置一个 Git remote，并正常 fetch、merge 审核过的提交。
同步保留上游历史和 OMS 历史，不重写远程分支，不删除旧标签或 Release。
`tools/upstream.json` 和 `tools/forks.json` 继续承担上游原有的 Cursor 同步职责，
不是 OMS 的第二套同步器。

每次更新核对生成器中的两处入口、T3 工具映射和 marketplace 名称，更新本页的基线提交。
修改生成器源后再生成文件，不直接维护生成后的副本。
OMS 的 VERSION 使用独立且递增的三段版本，保证同一上游版本上的适配修复也能触发插件更新；
它与本页记录的 pstack-claude 版本分别展示。发布时不要用上游 VERSION 覆盖 OMS VERSION。

检查使用 README 中的生成器和测试命令；其他上游检查按 CONTRIBUTING.md 执行。
测试不调用真实模型。原生技能发现、T3 代表性调用和不同后端的结果分别验收，不能相互替代。
