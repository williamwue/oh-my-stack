# T3 Code 适配

## 基线与差异

OMS 2.0.2 基于 michael-denyer/pstack-claude 0.9.138，提交为
`a12b04786023e762f12f5de7bb5fafb8c23f8c36`。
仓库通过保留双亲的合并接入上游历史，后续直接合入 pstack-claude；不独立同步官方 Cursor pstack。

OMS 的运行时差异限于：

- `poteto-mode/references/t3-tools.md`：T3 工具映射。
- `setup-pstack/references/t3.md`：T3 跨 provider 模型发现、配置和验证。
- `tools/generate.mjs`：为角色技能、Codex 工具映射和 setup-pstack 生成条件读取入口。
- 原生 marketplace 名称改为 `oms`，插件名和技能命名空间仍为 `pstack`。
- OMS 自身的版本、文档、适配测试及旧版证据归档。

上游模型表、工作流步骤、hooks、其他宿主适配和原作者声明保留。
T3 通过现有后端安装插件，不作为新的模型供应商或独立运行时加入上游 RUNTIMES。
现有个人角色配置不属于插件默认值，不随源码更新写入。

## 加载方式

代理读取 poteto-mode 时，条件入口要求它在会话提供 T3 Code 工具时读取 T3 映射。
Codex 工具映射也有同样的入口，避免直接进入其他技能后误用 Codex 派发方式。
setup-pstack 的条件入口在原生模型枚举和配置步骤之前引入 T3 配置规则。
角色技能的入口直接从上游 models.json 的 skill 字段推导，直接调用 how、swarm 等技能也会读取 T3 映射。
生成器维护这些入口，并使用上游的链接校验检查引用是否存在。
没有 T3 工具时，条件不成立，继续遵循上游行为。

映射仅保留 pstack 操作到宿主工具的必要对应。调度、完成通知、取消、链接、浏览器、
设备及秘密输入等通用规则以 T3 当前注入的指令和工具 schema 为准，不在插件里复制维护。

此机制依赖宿主向会话提供插件技能，以及模型遵守读取指令；它不是额外的执行引擎。
上游和宿主的权限规则仍然有效。T3 映射不授予派发、外部写入或发布权限。

## 跨模型配置

在提供 T3 工具的会话中运行 setup-pstack，使用宿主当前 catalog 选择 provider 实例、
完整模型 ID 及该模型支持的 effort。角色、panel 数量和确认步骤沿用上游。
T3 使用单独的 Markdown 模型表，保留原生配置的合法性。

| 范围 | 路径 |
| --- | --- |
| 用户 | `~/.t3/pstack-models.md` |
| 项目 | 仓库根目录的 `.agents/pstack-models.t3.md`，非 Git 会话使用起始目录 |

项目表整体替代用户表，缺失角色沿用后端原有配置。行值为
`providerInstanceId/full-model-id @effort`，panel 仍用逗号分隔。
`auto` 和 `inherit-parent` 保留父会话的 provider 和模型。
`default effort: session` 取父会话当前值，不能取模型目录的默认值。
跨 provider 时只传目标模型也支持的 effort，不自动把不同取值翻译成另一个取值。

模型按当前 catalog 及约束逐项验证，不可用的配置会报告并要求修正，不静默换模型。
T3 派发前读取表，将 provider、模型和目标模型的 effort option 分别传给宿主。
配置不会修改父会话模型、全局指令、原生模型表或 hook 信任，也不会自行启动工作。
子任务简报携带生效模型表的绝对路径，使 worktree 内的后续角色派发使用同一项目选择。

这是 OMS 的 T3 配置约定，不是 T3 官方的配置文件格式。
完整代理执行说明见 [setup-pstack 的 T3 参考](../plugins/pstack/skills/setup-pstack/references/t3.md)。

## 维护与同步

维护者为 pstack-claude 设置一个 Git remote，并正常 fetch、merge 审核过的提交。
同步保留上游历史和 OMS 历史，不重写远程分支，不删除旧标签或 Release。
`tools/upstream.json` 和 `tools/forks.json` 继续承担上游原有的 Cursor 同步职责，
不是 OMS 的第二套同步器。

每次更新核对生成器中的 T3 入口、工具映射、模型配置和 marketplace 名称，更新本页的基线提交。
修改生成器源后再生成文件，不直接维护生成后的副本。
OMS 的 VERSION 使用独立且递增的三段版本，保证同一上游版本上的适配修复也能触发插件更新；
它与本页记录的 pstack-claude 版本分别展示。发布时不要用上游 VERSION 覆盖 OMS VERSION。

检查使用 README 中的生成器和测试命令；其他上游检查按 CONTRIBUTING.md 执行。
夹具测试不调用真实模型。用户授权的真实调用单独记录；原生技能发现、T3 代表性调用
和不同后端的结果分别验收，不能相互替代。
