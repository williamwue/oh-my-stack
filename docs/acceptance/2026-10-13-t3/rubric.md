# T3 design acceptance criteria

Each criterion is graded against concrete caller behavior and repository boundaries.

1. Default host generation and pinned workflow semantics remain unchanged. T3 is explicitly selected and native installation formats remain authoritative.
2. Provider, model, and typed options come from the observed catalog. Configuration is isolated and ordered panels survive reruns.
3. A small public API prepares complete delegated tasks and represents requested and observed execution separately. Retries retain identity and new rounds receive fresh identity.
4. Task return, nested work, cancellation, and unavailable capabilities cannot produce a false completion claim.
5. PR, scheduling, browser, and device bindings follow current T3 contracts. User authorization still controls external actions and top-level conversations.
6. The design fits deterministic generation and behavioral tests without a daemon, additional credentials, or scattered copies of host policy.
