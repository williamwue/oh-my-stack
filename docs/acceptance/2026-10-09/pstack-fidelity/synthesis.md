## Design decision

The configured three-entry panel produced the complete candidates retained in
`design-1.txt`, `design-2.txt` and `design-3.txt` as path-redacted display copies;
`design-freeze.json` binds original and display bytes. Exact original candidates
and prepared requests remain in private scratch. The distinct judge's full
result is `design-judgment.txt`. All candidates
preferred a stateless acceptance packet and described a structurally different
event-ledger alternative. This comparison does not claim three different
preferred architectures.

Select candidate 2's frozen requirements and observed local verification.
Graft candidate 1's shared workflow reference and separation of exact parity
from an approved changed appearance. Reject the durable-ledger alternative for
this bounded repair: it would add lifecycle migration and duplicate ownership
without establishing the missing observed checks. Reject candidate 3's singular
writer/review graph and successful full result with unknown provenance.

The judge assessed every rubric criterion qualitatively; no numeric scale was
defined and no scores are fabricated. The rubric was frozen after candidate
production and before judgment; candidates did not receive it.

## Implementation contract

One portable CLI freezes requirements, inspects pinned evidence without running
commands, and verifies selected frozen checks by executing them. Actual source
bytes, additions, deletions, immutable harness/configuration and evidence
freshness determine the artifact revision. A separate expected lock digest
anchors continuity. The root still chooses meaningful scope and assertions.

A pure internal PNG comparator measures supported original RGB/RGBA images.
Intentional redesign uses an approved frozen target; region masks are deferred
and unsupported input fails closed. Pixel equality does not authenticate a page
capture or establish usability.

`provenance-addendum.txt` specifies the supported optional native completion
protocol. The observed final envelope uses `phase: final_answer`; the addendum's
proposed `channel: final` is superseded by this observation. The adapter verifies
runtime-recorded declarations and distinct child identity, not authorship or
review quality. It requires an exact recorded assignment. Unknown host receipts
and encrypted assignment text remain unverified.

## Evidence boundaries

distinct child IDs from this thread's native records. Spawn messages are
encrypted, so exact role/task text could not be audited. Those observations do
not retrospectively create completion declarations or certify full provenance.

Historical conformance records retain their original claims. Current fixture
passes establish current local behavior only. A same-task original-pstack
comparison, installation activation, real browser capture and production
