# Candidate 1 — Native filesystem identity

**Design only; no implementation changes.**

## Problem and preserved constraints

At baseline `df3597a`, native Windows paths fail comparisons against slash-form evidence references, snapshot prefixes, repository-containment prefixes, and executable patterns. A read-only probe confirmed all four mismatches. All 208 semantic-derivation file references currently match their raw-byte SHA-256 values.

Preserve raw-buffer hashing, provenance records, generated bytes, evidence relationships, inventory requirements, and credential rejection. Snapshot exemptions apply only to Markdown resolution and upstream home-path examples; snapshots remain subject to hashes and credential checks.

## Caller usage

```js
await validate(root); // Existing public API and returned model.

const file = manifestFile(root, record.evidence, context);
const evidence = evidenceByFile.get(file);
assert(evidence, `${context}: missing evidence ${record.evidence}`);
```

Discovered files and parsed manifest references become native absolute paths. Documents retain canonical slash references.

For Markdown, resolve decoded destinations against the document directory, then check containment. `../README.md` may pass; repository escape must reject.

## Shape and ownership

Keep private helpers in `tools/validate.mjs`:

```ts
manifestFile(root, input: unknown, context): NativeAbsolutePath
within(root, candidate, allowRoot = false): boolean
validationFiles(root, directory, { excludeSnapshots = false }): Promise<string[]>
```

`manifestFile` rejects empty/non-string values, NUL, backslashes, Windows/POSIX absolute paths, drive-relative paths, empty components, `.` and `..`; then resolves natively.

`within` checks `relative(root, candidate)`: reject `..`, a `..` directory prefix, or an absolute result. Explicitly handle root equality.

Extend `filesUnder` in `tools/generate.mjs` with optional `excludeDirectory(absoluteDirectory)`, evaluated before descent. Default behavior remains unchanged.

Validation traversal prunes directory components named `node_modules` or `.git`, plus the exact repository-root `.tmp` subtree. Only Markdown traversal additionally prunes snapshots. Public hygiene still reads snapshots.

Migrate evidence maps and executable inventory sets to native absolute identity. Classify executable directories using native membership/components. Apply native scope checks to semantic source/output paths and parsed upstream import locations. Preserve serialized ownership text.

Existing model loading and rendered-package checks remain unchanged; their explicit roots avoid root scratch/dependencies. Nested dependency installation inside source-model directories remains unsupported. Tests belong in existing Markdown tests and new focused validation tests.

## Tradeoffs and rejected alternative

Native identity avoids repeated conversion between logical keys and filesystem paths; diagnostics retain original references. Reject a universal slash-key abstraction because these identities are transient and filesystem operations dominate. Existing portable `treeMap` keys remain appropriate.

Containment remains lexical: symlink/TOCTOU hardening is outside this patch. Validation performs no writes or automatic retries; acceptance uses isolated checkouts.

## Executable acceptance

Run focused tests, `npm run validate`, and `npm run check` on Windows and POSIX.

Positive fixtures: slash evidence/related references; internal parent-relative Markdown links; snapshot template links/home-path examples; exact provenance bytes; ignored dependency/scratch documents.

Negative fixtures: missing/wrong-profile evidence; repository/sibling/drive escapes; malformed manifest references; missing authored links; unlisted tool/skill scripts; snapshot credentials; one-byte provenance mutation; semantic output escaping `src/core`.

Also require `node_modules-notes` and `snapshots-copy` remain checked, and generic generation-tree comparison still detects unexpected files. First unit: evidence identity plus relationship rejection tests.
