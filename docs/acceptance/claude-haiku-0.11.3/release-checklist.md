# Oh My Stack 0.11.3 release checklist

Scope: include Haiku in default Claude observations and the dynamic three-family
recommendation. The maintainer authorized publishing the new version and updating
local plugins and the Claude model mapping. Keep the medium budget targeting
high, Codex mappings, project overrides, unrelated plugins and hook trust.

## Candidate gates

- Complete full repository checks and the bilingual book audit in the pinned
  local release environment.
- Observe Haiku, Sonnet and Opus through three bounded authenticated probes.
  These establish canonical identities, not child execution or effective effort.
- Install candidate packages through native Codex and Claude managers in isolated
  homes, verify exact installed bytes, and exercise detached configuration from
  the observed inventory.
- Freeze the reviewed source tree and patch; complete independent read-only
  candidate reviews and root judgment, resolving actionable findings.
- Preserve the original worktree and back up personal OMS model files.

## Publication gates

- Land the reviewed source, then create the matching version tag from a clean
  checkout. Bind the completed review verdict to its exact tree.
- Use the official pinned Node 22.23.3 and zlib 1.3.1-e00f703 with the current
  local maintainer pipeline; require full checks and reproducible tagged builds.
- Verify all seven draft and public assets and gated stable promotion.
  Historical CI is not fresh release evidence; Actions is optional under the
  current local release policy.

## Local update gates

- Retain previous release files and native marketplace source types/scopes.
- Update only OMS through native plugin managers and verify complete cache
  inventories against the published manifest.
- Preview and apply the observed three-family Claude mapping at user scope,
  retaining the requested high target and three ordered panel positions.
- Audit every owned configuration file and effective scope. Check fresh-session
  Skill discovery; report child model/effort and workflow coverage separately.

This checklist specifies gates; it does not claim they have already completed.
Execution evidence is retained outside the source checkout.
