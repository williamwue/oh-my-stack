# Oh My Stack 0.2.0-alpha.8

Status: public GitHub prerelease. This release improves setup reporting and
acceptance; it does not claim full Cursor behavioral parity.

## Changes since alpha.7

- Setup checks both the observed model inventory and the active runtime's
  delegation capability before applying a project-scoped mapping.
- The applied resolution records whether the named budget is a reasoning
  *target* (OMP pstack preset) or *ceiling* (Codex). Neither is a token or
  money limit. Setup must show each effective route choice, including any
  low-effort deep route or high-effort panel member.
- `scripts/setup-acceptance.mjs` checks all owned generated role hashes without
  editing them. With fresh parent and child records, it verifies one OMP native
  role or Codex explicit spawn, including the resolved model and effort. An
  artifact-only check reports activation as unverified.
- Setup asks for a bounded, read-only child probe after apply, unless the user
  requested configuration only. One passing route does not certify all
  workflows, panel fan-out, provider diversity, or another project.

## Try OMP setup

Start a fresh OMP session in the intended project after upgrading the package.
Invoke `setup-oh-my-stack`, review the complete model and reasoning table, and
accept only the choices you want. The setup workflow will identify the project
manifest, audit its files, and request a read-only one-worker smoke test.
Inspect the result's separate `configuration` and `activation` fields; do not
read `configuration: verified` as proof of model routing.

## Verification boundary

Automated fixtures cover OMP native-role and Codex explicit-spawn acceptance,
including mismatched effort and fallback failures. OMP previously selected a
project-scoped role on a live 18.2.11 probe. A new user's OMP setup and its
fresh child record still require that user's run; this release does not
pre-certify it. Claude Code live use remains deferred.
