# Oh My Stack 0.6.0

Prepared on 2026-10-04 for the explicitly requested release of the reviewed
post-0.5.0 work. The public catalog remains 74 Skills across Codex, OMP and
Claude Code. The latest published book content is retained from `main`.

## Behavior

- The source release installer executes correctly through file and directory
  aliases, including macOS `/tmp`, and reports malformed commands as failures.
  Importing its module still does not execute the CLI.
- The Codex GitHub provider adds read-only `diagnosePr()`. It reports bounded
  current-head, GitHub-App-pinned required check identities and distinguishes
  passed, failed, pending, missing and unknown observations. Concrete
  mergeability state is exposed without treating every blocked check as a
  source conflict. This method creates no journal and performs no mutation.
- Policy structure is audited before reporting failed CI. Malformed check/status
  observations stay unknown/non-ready. Unknown review rules and populated
  dismissal/bypass restrictions stop safely; documented empty collections are
  accepted. This narrows unsupported policy acceptance and preserves merge
  authority and actual repository approval requirements.

The existing single-PR workflow still supports babysit check only. The
[assisted drive design](../github-babysit-drive-design.md) is selected but its
push/recovery implementation is not included. No autonomous repair, multi-PR
queue, automatic orphan-lock reclamation or worker reattachment is claimed.

## Acceptance scope

The [continuation record](../checklist-continuation-2026-10-03.md) documents the
preceding source review and 235-test gate. Its native host observations concern
installed **0.5.0**, not fresh 0.6.0 activation. Codex/Claude Skill and child
smokes and saved-parent pickup passed within that scope; OMP model execution
was blocked by its native login. Claude child effort, contained child
cancellation, late-result fencing and broad Windows/Linux interactive coverage
remain unverified. Benny/Webhook acceptance remains deferred by the user.

Version-specific release gates are independent review of the exact candidate,
the full source gate, deterministic clean tagged builds, GitHub CI, all three
runtime archives' install/update/rollback/verify lifecycle, isolated native OMP
package discovery/doctor/Skill loading, and downloaded-asset comparison.
Native OMP package checks do not require or certify an authenticated model turn.
Fresh model-facing host parity is not an added capability of this version.
The publication receipt records the actual revision, commands and outcomes;
these gate requirements alone do not assert successful publication.

Personal plugin upgrades and model configuration are separate from publishing
this release. Retain trusted 0.5.0 assets for rollback.

## Candidate verification

The versioned candidate passed the full **235-test** source gate. All three
runtime packages passed 0.5.0 install/verify, 0.6.0 plan/update/verify, rollback
to 0.5.0, and a second 0.6.0 update/verify, followed by uninstall. The isolated
OMP 0.6.0 native gate passed installation, doctor, Skill loading and cleanup.
These are candidate results; exact-commit independent review, tagged builds,
remote CI and downloaded release verification remain publication gates.

The development-only Markdown lint dependency chain reports five affected
package entries for the single
[braces advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).
The advisory lists no patched version at release preparation. The repository
uses fixed, versioned lint patterns; runtime archives do not include this
lint toolchain. `npm audit --omit=dev` reports zero vulnerabilities. The existing
pinned toolchain is retained rather than applying npm's suggested downgrade to
markdownlint-cli2 0.0.4. This is a disclosed source-development limitation,
not a claim that the advisory has been fixed.
