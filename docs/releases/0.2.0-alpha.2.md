# Oh My Stack 0.2.0-alpha.2

This is the first public-Alpha release candidate. It packages the existing
portable workflow core for OMP, Codex, and Claude Code while making the
project's installation, security, contribution, provenance, and verification
boundaries understandable to developers outside the original workspace.

No public repository, tag, or hosted release is implied until those external
operations are completed separately.

## What changed

- Added a newcomer-oriented target support matrix and quick start.
- Added `CONTRIBUTING.md`, `SECURITY.md`, `CHANGELOG.md`, and a public evidence
  policy.
- Added the planned public repository URL to package and Codex plugin metadata.
- Added a repository validation gate for private runtime files, absolute local
  home paths, private-key blocks, and common token shapes.
- Changed the remaining unowned schema identifier to the reserved `.invalid`
  namespace.
- Preserved exact historical runtime evidence without publishing the private
  transcript stores that created it.

## Release artifacts

`npm run release:build` creates:

- `oh-my-stack-omp-0.2.0-alpha.2.tar.gz`;
- `oh-my-stack-codex-0.2.0-alpha.2.tar.gz`;
- `oh-my-stack-claude-code-0.2.0-alpha.2.tar.gz`;
- `oh-my-stack-codex-plugin-0.2.0-alpha.2.tar.gz`;
- `release-manifest.json` with runtime and plugin-bundle inventories;
- `SHA256SUMS` for all archives and the manifest.

## Codex installation

Extract the plugin archive, register its marketplace root, and install the
plugin:

```bash
codex plugin marketplace add /absolute/path/to/oh-my-stack-marketplace
codex plugin add oh-my-stack@oh-my-stack
```

Start a new Codex task after installation so its bundled Skills are loaded.

## Verification boundary

The release inherits the runtime evidence recorded by earlier candidates; this
documentation and metadata hardening does not manufacture new live evidence.
Codex CLI has the strongest installation and workflow evidence. OMP retains an
unresolved native plugin-manager dry-run safety gate. Claude Code live
discovery and end-to-end verification remain explicitly deferred until an
authenticated local runtime is available.
