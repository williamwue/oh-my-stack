# Long Skill loading diagnosis and candidate fix

## Result

The four long installed Skills were incomplete in the tested model context,
not merely shortened in the displayed log. A new read-only turn selected the
four original installed entries and prohibited tools or file reads. Asked for
their final heading and lines, the model reported `CUT_OFF` for all four and
returned the same partial lines found in persisted instructions.

This reproduces the behavior on Codex CLI 0.155.1. It does not locate the exact
internal function or establish a universal 8,000-character limit for all Codex
versions. The diagnostic session was
`01a0cb70-3109-7c52-922d-1adb442dad10`; raw logs are retained in the ignored
`.tmp/long-skill-diagnosis` directory.

The generator now avoids this behavior for the candidate Codex package. The
published and installed alpha.4 package remains unchanged and still needs a
separately versioned update.

## Bounded implementation

`tools/generate.mjs` keeps each Codex entry at or below a conservative 7,500-byte
budget. When the rendered document exceeds that budget, the generator writes
the original complete document unchanged to `WORKFLOW.md` beside `SKILL.md`.
The entry retains its name, description, heading, and invocation metadata. It
requires reading the complete workflow before applying it and stopping if the
file is unavailable. Loading does not authorize workflow actions.

Keeping `WORKFLOW.md` beside the entry preserves all original relative links.
The generator refuses to overwrite an existing source file with that reserved
name. Four current entries use this form; all 49 remain directly selectable.
OMP, Claude Code, core instructions, and upstream provenance records are unchanged.

OpenAI Docs informed the protocol checks; its
[Skill documentation](https://learn.chatgpt.com/docs/build-skills) describes
packaged instructions and supporting resources. Skill Creator guided the short
entry and linked procedure design. This change preserves existing procedure
content instead of treating the measured limit as a reason to remove rules.

## Failing-before and passing-after checks

Before implementation, this new regression exited 1 at
`reproduce-and-fix-issues: direct entry exceeds safe injection budget`:

```bash
node --test --test-name-pattern='Codex long direct entries' tests/generate.test.mjs
```

After implementation, the same test passed. It generates a fresh Codex package,
checks every public entry's byte budget, and compares the complete procedure
against the source body without deleting any instructions. The existing metadata
test still checks all direct entries, descriptions, categories, and invocation
policy, and follows the linked procedure for its unchanged-body assertion.

`npm run generate` regenerated packages. `npm run check` passed generation,
conformance, reproducibility, schema, Markdown, and all 83 tests. There was no
diff in the OMP or Claude Code packages, core sources, or upstream records.
The Skill Creator Python validator could not run because PyYAML was unavailable;
that optional check is not counted as passed. No Python dependency was installed.

## Live candidate acceptance

The generated Codex skills were copied into an isolated project's `.agents/skills`
directory. Five fresh native app-server sessions selected batches of 10, 10,
10, 10, and 9 entries with structured Skill inputs. All 49 persisted entry
bodies matched their files in full. Names and headings also matched, and no
tool calls were observed in these metadata-only turns.

Four additional fresh sessions inspected the long procedures without executing
their workflows. Each model followed its entry to `WORKFLOW.md`. The root
compared actual command outputs with the full files, not just model summaries.

| Entry | Entry bytes | Complete read | Final heading and lines |
| --- | ---: | --- | --- |
| `reproduce-and-fix-issues` | 712 | Exact full text in tool output | Match |
| `setup-benny` | 669 | Exact text across three contiguous reads | Match |
| `technical-writing` | 702 | Exact full text in tool output | Match |
| `triage-issue-reports` | 709 | Exact full text in tool output | Match |

Each `WORKFLOW.md` also matched the corresponding original installed alpha.4
`SKILL.md` byte-for-byte. After the runs, the candidate directory's file
inventory matched the generated skills tree. No workflow actions or delegation
were observed. The
[machine-readable results](0.2.0-alpha.4-long-skill-results.json) preserve entry
hashes, read commands, session IDs, and raw-log hashes.

The first read-result checker rejected `Review checklist` because it expected
the Markdown prefix `##` and a space. Normalizing that heading marker resolved the checker
format mismatch; no model rerun was needed. Full-text and final-line equality
assertions remained unchanged. Local diagnostic script preparation also had a
JavaScript quoting error before any turn ran; it was corrected before the
recorded diagnostic session.

## Remaining boundary

These are generated-candidate checks, not a native marketplace installation
upgrade. The actual installed alpha.4 has not changed. A local versioned build,
installation, and repeat of discovery and complete-read checks remain required.
The original failing installed-entry evidence is retained.

The live tests inspect instructions. They do not execute Benny integrations or
prove every workflow behavior. Desktop UI, automatic invocation, and Claude Code
live verification retain their earlier status. No commit, push, or release was
performed.
