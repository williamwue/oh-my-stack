## Read-only trace and structural change

The simple `how` inspection traced `buildRelease`, its callers in the release
tests and CLI, and its call to `buildPluginBundle`. Both build paths computed
the same four fields: archive SHA-256, byte size, inventory SHA-256, and inventory.
The inventory hash also duplicated the same serialization and trailing newline.
This initial source inspection made no implementation changes.

The refactor introduces one private pure function, `archiveMetadata`, and
replaces both field blocks with calls to it. No exported API changes. Archive
creation, filesystem operation order, validations, cleanup, and object field
order remain unchanged. The measurable reduction is two metadata definitions
to one, not fewer total lines. No generic packaging abstraction was introduced.
No experiments were reverted and no tests were weakened.

## Contract pinned before editing

1. Built all release artifacts into a fresh temporary directory with
   `buildRelease({ out })`.
2. Recorded `packageInventory(out)`, covering paths, sizes, normalized modes,
   and SHA-256 values for all six output files.
3. Ran `node --test tests/release.test.mjs`: all eight tests passed.

After the refactor, the root rebuilt into another fresh temporary directory and
compared the complete inventory with the retained baseline. Result:
`exactInventoryMatch: true`, six files. The
[before/after inventory](0.2.0-alpha.4-refactoring-inventory.json) preserves both
observations, including the manifest and SHA256SUMS, not just package archives.

The same build-and-inventory operation was used on both sides:

```javascript
const out = await mkdtemp(join(tmpdir(), "oh-my-stack-refactor-"));
try {
  await buildRelease({ out });
  console.log(JSON.stringify(await packageInventory(out), null, 2));
} finally {
  await rm(out, { recursive: true, force: true });
}
```

`mkdtemp` and `rm` come from `node:fs/promises`, `tmpdir` from `node:os`,
`join` from `node:path`, and the two project functions from the build and release
library modules. The comparison covered the preserved snapshots, rather than
merely checking that the new implementation reproduces itself twice.

The root reviewed the actual diff and then ran `npm run check`: all generation,
conformance, reproducibility, schema, and Markdown checks passed, as did all
82 tests, including the eight release tests. `git diff --check` also passed.
Temporary build directories were removed; no user installation was removed.

## Boundaries and next task

current platform. Snapshot hashes are not new published release checksums;
future package or provenance changes can legitimately change them. Error-path
regression tests also passed, but this does not exhaust concurrent filesystem
failure modes or establish every possible input's equivalence.

triggering. This record does not advance a host-wide capability level or claim
