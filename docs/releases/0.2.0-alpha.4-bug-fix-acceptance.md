## Defect and cause

The generic installer should replace an existing destination only after its
ownership marker identifies an Oh My Stack installation for the selected target.
Instead, `installArchive` caught `ENOENT` from both ownership-marker reading and
destination replacement as though the destination itself did not exist.

For a pre-existing empty directory with no `GENERATION.json`, the ownership
check therefore fell through to the staged rename. On the tested platform,
that rename succeeded and took over the unowned directory. This was not an
observed loss of user file contents; the reproduced target was empty.

## Bounded fix and root verification

whether the destination exists. Only an absent destination takes the initial
installation branch. For an existing destination, ownership failures propagate
instead of being swallowed. No CLI flags, Skill instructions, or packages changed.
