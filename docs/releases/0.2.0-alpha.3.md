# Oh My Stack 0.2.0-alpha.3

This public Alpha corrects the boundary between user-facing workflows and
internal runtime conformance probes.

## What was broken

The canonical catalog correctly classified 49 Skills as public and 12
`check-*` Skills as internal probes, but the target generator packaged all 61
into every runtime archive. A real Codex installation therefore exposed test
probes to users and contributed unnecessary Skill descriptions to the session
context budget.

## What changed

- OMP, Codex, Claude Code, and the Codex marketplace bundle now contain only
  the 49 public Skills.
- The 12 internal probe Skills remain canonical source material under
  `src/core/skills/`.
- `npm run generate:probes` builds disposable full-catalog target trees under
  `.tmp/probe-packages/` for runtime conformance work.
- Package and release tests reject any `check-*` path in public artifacts.
- Generated metadata records the included audience and omitted probe count.

## Verification

The original regression test failed against `0.2.0-alpha.2` because every
committed target package contained all 12 probe directories. The same test
passes after the generator split: each public package has 49 Skills and zero
probes, while each test-only target has all 61 Skills and 12 probes.

The release archives remain deterministic and retain the existing provenance,
checksum, lifecycle, and capability-evidence gates.

## Runtime boundary

This packaging correction does not broaden existing runtime claims. Claude
Code live verification remains deferred, and OMP retains its documented native
plugin-manager safety limitation.
