# Oh My Stack 0.2.0-alpha.11

This maintenance prerelease follows the user-level setup and route-parity
changes in alpha.10. It fixes a real Codex CLI acceptance-record format issue
and records the latest bounded setup observations. It is **not** a beta or a
claim of complete Cursor pstack parity.

## Changes since alpha.10

- The Codex setup verifier now recognizes padded encrypted spawn messages in
  persisted parent records. It still requires one matching explicit spawn,
  linked parent/child session IDs, and the configured model and reasoning
  effort in every child turn context. It reports encrypted message text as
  unreadable rather than claiming to have checked it word-for-word.
- OMP and Codex user-level setup retain 20 route keys each: 19 pstack-style
  logical choices plus the `code.delegates` compatibility route. Existing
  project manifests, when present, still override the user default.

## Observed setup acceptance

On 2026-09-24, OMP 18.3.0 selected the user-level `how.explorer` native task
agent and completed a read-only file-heading task on
`openai-codex/gpt-6-luna` with high thinking. Codex CLI 0.155.1 completed the
same bounded task through an explicit spawn using `gpt-6-luna` at high
reasoning; parent and child session records matched. These are one-route
observations, not verification of every named route, multi-worker panel,
Codex native custom-role selection, or provider diversity. A separate
Codex Desktop subagent turn also exposed Luna at high reasoning, but its
first task instruction prevented file access and was not counted as a
completed workflow.

## Installation and remaining boundaries

An isolated OMP 18.3.0 profile still created a plugin link and lock entry
during `plugin link --dry-run`; the disposable plugin was subsequently
uninstalled. Do not use that command as a read-only installation preview.
The OMP package and owned-directory release installer pass their separate
checks, but the native plugin-manager D1 safety gate remains open. Codex's
marketplace lifecycle and the repository checks pass. Real external-system
W4 flows, exhaustive workflow execution, Codex Desktop picker coverage, and
authenticated Claude Code use remain unverified or deferred. Users should
review target permissions before granting write, network, merge, or deploy
authority.
