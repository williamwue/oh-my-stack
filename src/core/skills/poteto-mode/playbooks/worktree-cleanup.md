### Worktree and simulator cleanup

1. Snapshot and audit. Record the current disk use and actual paths from `git worktree list`. Read the installed runtime binding for its supported read-only audit, active and pinned session interfaces, and evidence contract. Use only that documented helper operation from the resolved installed package. The source-host worktree-audit.sh is reference material, not an executable native cleaner. Missing supported host observations remain unresolved.
2. The bucket is advice, not permission. Read the actual active and pinned session set through supported host interfaces and cross-check every candidate. A bucket cannot override a pinned or active session. If this evidence is unavailable, retain the candidate as unresolved.
3. Verify usage before proposing removal. Inspect each candidate's owning sessions, live child tasks and processes through the installed binding. Child worktrees can be active even when absent from the main session list. Use authorized exact-session transcripts only when supported, and do not infer pin state from a transcript. Unknown ownership or liveness is a hold.
4. Preserve work before any deletion proposal. Tracked, untracked and ignored files may be unique user state. An empty diff does not prove their absence. Inspect status with untracked and ignored paths, submodule state, locks, active and pinned sessions, child writers, and HEAD-reflog-only commits through the installed read-only audit contract. Missing or stale host evidence leaves the candidate unresolved. Never treat `scratch:N`, a cache name, or a clean tracked diff as disposable-file permission. Preserve detached and reflog-only commits with durable refs before any authorized removal. Submodule work and commits require their own preservation. A lock is a hold, not a reason to force around it.
5. Return the exact advisory candidate set and evidence for an explicit cleanup decision. Never delete automatically from a bucket, force-remove a locked tree, or fall back to recursive directory deletion. Removal can destroy a worktree's HEAD reflog and submodule-local history even when branch refs survive. Cleanup execution needs separately authorized exact paths and the installed host procedure. This workflow text does not grant deletion authority.
6. List simulator and cache candidates separately. Use supported host inventory to identify stale devices, runtimes, build output and caches. Preserve requested artifacts, recent transcript evidence, configuration and unknown files. Return exact candidates and the evidence for a cleanup decision. Do not run simulator deletion, recursive removal or cache clearing automatically.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
